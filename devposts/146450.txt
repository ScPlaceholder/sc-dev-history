While the build times for the game are pretty huge, when we're just iterating on things locally we use a tool called Incredibuild which shares work around the network to speed things up. The purpose of the build server (which also uses Incredibuild for code) is to have a single central point to produce a definitive single build from all the work that's been submitted as finished, which is then available to the test/art/design/etc teams. The build server is also responsible for running all the resource compilation to produce a definitive set of art assets etc. It doesn't take an artist too long to recompile the asset they're currently working on, but doing a full resource build of all the game's assets takes quite a long time, so it's definitely valuable to have it done by an external server.
We also have a helpful system called TryBuild, which will do a code build of the game with everything that's currently checked in plus one unsubmitted set of changes. We're not allowed to check in a code change without TryBuild giving the green light that our change will compile as a development build, server build, and release build, so we can catch a lot of trivial incompatibilities before they're checked in. Checking out code only to find it doesn't compile at all is a disruption that can cost hours of work across the team, so that's really good for avoiding those problems.
