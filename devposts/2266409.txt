Hey @pifroggi, thanks for your question. Essentially Star Citizen (or more precisely its engine) is able to do just the same thing as in the video you are describing ... and in fact, we have used raycasting like that in past ... but for multiple reasons we had to dial back on their use.
The biggest problem is the scale of the game. A raycast for footsteps does not cost much ... because the audible range for feet is only a couple of meters ... but we have audio sources which can be heard for miles. And this produces the problem of the length of a raycast. The longer the ray is the more checks need to be done to figure out which object in the world is stopping a ray. Which means a longer ray can massively be more expensive in terms of CPU time. Especially on planets that was a problem because a longer ray would force the terrain to become physicalized beyond the normal boundaries ... which in turn caused huge CPU spikes. So if we'd use raycasts everywhere where we wanted to ... it would make the game extremely slow. There are quite a lot of more reasons ... but the bottom line is that SC has a tougher job due to the scale and the fact that everything moves all the time.
The good part of that problem is that we're forced to look at different ways to handle that ... we have already plans laid out to approach the exact problem you're describing. I cannot go into details here as we have not started implementing that part (my rough estimate is post 3.8). But it will work out in the end.
Hope that helps. :slightly_smiling_face:
