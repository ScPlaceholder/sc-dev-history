The patches and updates _still_ need to go through the build and testing processes. The patcher changes allow us to deploy smaller patches and most importantly, won't force you guys to download a large differential if it is not needed. (unlike the current version of the patcher).
The scheme you describe of releasing a ship in a "version stream" and shortly after releasing a major update is possible indeed but is not necessarily related to the patcher itself but more to how the builds and branches are used and planned. Of course, the ability to deliver smaller patches is a win in that scenario because it removes a major hurdle when creating and transfering the builds to players.
The server and client version in games usually are set to always match in order to ensure versions of the communication protocols are the same during a play session and so usually a client patch requires a server update/restart if the versions have changed. This can sometimes be independent of the actual client version but more related to the protocol version. With this game being under active development in all areas of the engine and server, there is mostly a protocol update every patch.
