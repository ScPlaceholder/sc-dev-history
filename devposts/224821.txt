In most cases, it's safe to assume that we (usually me) are going to make a new database for major releases. While we don't wipe the database data, we do often times make a new database (depending a number of things) so that accounts get a fresh start with the new version of the game. When we do this, accounts that log in won't have any of their aUEC items from the previous build because we don't import item data from previous databases.
Some examples of things that we look at when deciding on if we need to make a new database prior to us releasing a build to our players are:
- Is there a new schema needed to support the new release? (This typically happens if we're adding new game systems that need to save their information to the database)
- Are there bugs that players have with their account (such at the Star Marine medium armor eva thruster issue) that would benefit from having a new database to test and see if it's still happening?
- Are there any bugs with item generation on new accounts that we need to test?
If we feel that we don't need to make a new database for a release, we'll continue using the most current database. In some cases, this can help to expose bugs that occur only when the same database is used from one build to the next.  We have had these bugs occur in the past and when they do occur, typically QA or Game Support are the first ones to identify that these problems are taking place. They'll bring them to my attention so that we can work together to figure out what the problem is and then get the issue documented as a bug for developers to look at. After that, we usually end up having to make a new database anyways to ensure that our players can play the game.
