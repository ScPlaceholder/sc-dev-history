I won't dive into the whys and whens, but since 32-vs-64 threads are basically catnip to me, I'll stop by to point out that this thread contains three entirely unrelated kinds of 64-bit-ification. They're orthogonal to one another and I think they were done at different times.
- 64-bit executable : Definitely necessary if you want to address more than 4GB of memory, which we do. This is the thing that you need a 64-bit processor and operating system to be able to run the game.
- 64-bit (aka double) floating point precision : I don't want to say that this is necessary for positioning things in a space more than about 5km, because there are other alternatives like segmenting space into chunks with separate origins, or using 64-bit integer precision instead, but certainly something is needed if you want a playspace wider than the Arena Commander boundary. Double-precision floating point has been available for much longer than 64-bit processors though, and it's entirely possible to use one without the other.
- 64-bit entity IDs : Explained well enough in your quote above, though again 64-bit, (and even 128-bit numerical types) have existed for a long time and don't need a 64-bit executable. Even without a native type to support it, we could (if we wanted to) have an ID of any size at all, though we'd pay progressively more memory, mem-bandwidth and processor cycles for operating on them, and really 9.2 sextillion is probably a big enough number to be going on with.
