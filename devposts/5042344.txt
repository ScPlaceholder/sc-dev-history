Sharing the server work between multiple servers/nodes should make those servers run much faster, but that may or may not reduce the amount of work that the client needs to simulate, so I'm unsure whether that will directly lead to better client performance. But how the performance cost scales with player/entity count and distance to other players/entities and what needs to be run on the client vs each server node will differ per system and is the responsibility of the other engineering departments, and so they'd be much better to advise.
It's really hard to summarise the many interelated engineering intitiatives that are proceeding in parallel to improve the game, especially because anyone with deep knowledge of one area (e.g. Gen12/Vulkan/rendering like myself) will be ill equipped to give accurate details on other areas like server meshing. But to summarise the situation for client performance, there's not a direct link between the server and client performance, and the way to make the client faster is to either make the client do less work, or to spread that work over more CPU cores (e.g. Gen12+Vulkan).
