Yes, that's pretty much the end result. The ping code normally accounts for the tiny amount of time spent processing the ping message - from the time it is read from the socket to the time the response gets sent back to the client. But the performance issue means the ping message can sit in the socket's internal receive buffer for a while before being picked up by the network thread. So the ping measured is the network round-trip time plus some random fraction of other network thread processing.
