The working set and commit size aren't concepts are directly controlled by any application, these are the responsibility of the operating system (see https://technet.microsoft.com/en-us/library/ff382715.aspx).
I'm not personally very familiar with how windows chooses to manage this, but my understanding is that if the commit size is larger than working set then this might imply memory has been allocated by the application, but hasn't been used for some time and therefore has been paged to disk to free the physical memory up for other applications. Without investigating myself I can't say why we'd have GB's of memory that isn't being referenced (though some amount is expected and unavoidable), however one possible explanation might be that we simply load too many entities, and this is where the Object Container Streaming feature which is currently being worked will help keep only the nearby entities in memory. I should note however that many other systems already do stream data (e.g. textures & meshes) and so these are unlikely to be allocating memory which isn't required.
