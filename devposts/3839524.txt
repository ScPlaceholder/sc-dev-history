I think that practically sums it up. The IK of the actor won't move until a specific offset in the base rotation has been achieved. The vectors rotation vectors (base, aim, look) are practically input vectors. I think a year ago or so we had a version where the head tracking offsets were actually limited by that but it felt really off and inconsistent because you could sometimes turn your head 90 deg to the left sometime only 45. The problem is that you lack a frame of reference without having a gun up. That felt really bad as it was completely unpredictable so we set for the current version of not restricting.
A thing we could try is to not allow any hip movements if any manual head movement is on ... so that way any mouse movement would instantly move the base rotation, so the feet would always shuffle around ... but frankly that would look really bad.
Another options would be to add a head tracking "forward" pointer when you don't have a weapon drawn to help with the alignment.
But the actual best option might be to not use the "toggle" option for head tracking when being on foot. Have you tried using the "hold" function in the bindings? What I usually do is to disable Head Tracking on foot via the head tracking options and assign LALT or Z to the head tracking hold binding. Because the hold function is an active key press action, it always works when pressed no matter what the options are set up to. That allows me to use head tracking on foot momentarily when I actually need it ... it is also easier to control as by default it uses relative offsets only.
