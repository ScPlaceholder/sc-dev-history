The information that we get from the PTU is super useful. However, there does end up being things that we find out on the public/live environment for a few different reasons.
1. There are bugs that are timing specific. The more people there are playing the game, the more obvious they become
2. There are also bugs that are only possible and get worse with more data flowing through the backend services. As things start to slow down, these kinds of issues become more frequent.
3. Sometimes there are things that are a combination of the first two points. Timing specific and require slowdown in the backend services.
4. Sometimes there are rare combinations of things like certain kinds of characters used in a character name ( I don't think I've seen any of these recently but I definitely found a few bugs like this when I was in QA ) and having more people playing the game can increase chances of seeing stuff like this.
5. Some kinds of bugs are easier to find for certain people. This is why having a diverse team both at CIG and for our PTU testing phase is important because people that think differently will find different problems.
In short, games are complex and break in silly ways but it's hard to be able to predict or find all of the issues. I think the responsibility for making things like this easier to find is on us and we do have conversations about how we can better find problems like this. Much like iterative game development, we're constantly iterating on the process that we use for publishing and testing the game as well in order to try and find things like this before they become a problem.
