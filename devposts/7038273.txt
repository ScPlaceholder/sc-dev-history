Regarding the testing for baseline stability and regression test and especially if something broke what worked before.
So, CTL is useful to test large groups of clients doing certain things (Currently not possible to test all features, as this needs some fixes or features from game teams which are currently occupied by other things). It is good to see performance, especially in spawning a lot of ships and clients flying those somewhere etc.
For lets say new features, that might break other systems, for this we use rather other methods and systems. So, most teams have embedded QAs who will test immediately that new feature, location etc. for a first smoke test, if it breaks anything. Basic tests, if a feature passes certain checks are being tested with every build being made. Daily, hundreds of time by our own internal test system. No one has to do anything for this, every studio has about up to 15 (I think, not sure) machines inhouse who are all the time, 24/7 downloading a build, do basic tests of the teams. Every team writes their own tests for certain things, like a chain load of levels as example, so it loads a level in client or editor, closes the editor or client, next level. Or Load a test level, fire different weapons etc.). So, a good bunch of loading stuff, using some simple things like seats, weapons etc. are being directly checked there already. Later QA does then more wider testing for certain builds that are planned to be used for the next release. Bugs encountered in the game as a player, are things that are more difficult to recreate automatically.
