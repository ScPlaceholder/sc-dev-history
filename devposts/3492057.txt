We're not developing these things in isolation from each other. When I said that VET doesn't handle HUD / MFD it means that we don't have ownership over design but we absolutely formulate our requirements and have influence on the outcome. E.g. the missile / CM changes in 3.11 required some data for the player to allow meaningful decisions during combat. So VET made some quick prototypes for the missile and countermeasure HUD widgets and set up the building blocks data hooks for them. However it was then handed off to the UI  / VFT teams as they need to make sure it fits on the HUD, sits well with the other elements and communicates what it needs to do (and doesn't conflict with future plans) ... and make it pretty of course (our prototype UIs are really hard to look at :smile: ). That process is quite typical for how we work together, the whole process is very fluid as we all want to achieve the best possible outcome.
