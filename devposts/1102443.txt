Everything you say is 100% valid, but unfortunately the reality is this isn't a priority for us right now. The old CryEngine motion blur has some issues (perf, memory, quality) and isn't just a case of us turning it on, and in addition it's completely unsupported on our newer GPU particles so that would need a fresh implementation. Rest assured if this was a 5 minutes of even 5 hour tasks we've have already taken a look.
The display is not blurring because we explicitly disable motion blur, depth of field and TSAA from 'nearby' displays to ensure perfect legibility. The cutoff distance is usually set at the distance of the depth of field focus, which tends to be on the screen you are currently using (if any). However it's not currently set up correctly in all situations which is what results in this problem. In this 3rd person camera the cutoff distance should really be set to zero because you are not 'using' any displays that require perfect legibility. This will be addressed at some point, but we have more pressing issues we need to address first for 3.2 and S42.
I'm not sure what type of entity the shell casing is, but given it is actual geometry it should be blurring, so I'm guessing one of the parameters passed to the renderer for this object isn't set up correctly by the code that spawns/renders this shell (e.g. it should have a unique object ID to allow us to find out it's position on the previous frame to apply the correct amount of blur), so might be a relatively easy fix.
