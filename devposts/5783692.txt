I am not from dev ops nor a perforce power user, but all developers at CIG use perforce so hopefully my insight will be mildly illuminating. This is what I know.
The build number comes from the last submitted perforce change list number that the build was built after.
Perforce assigns these numbers automatically upon change list submits across all streams in perforce. Change list can contain one or more file changes at a time. Although the submits always have a unique and always increasing number, the number used is not always consecutive, so although it could be read to imply that there have been 8,389,318 submits that may not be the true number it could be significantly less. Additionally  those submits are from all over perforce in differing streams, not just the one the build came from.
This is also why simply subtracting one build number from another becomes a pretty useless metric because not only might those submit numbers not be consecutive but the number of actual file changes for each number can be any number of changes and many of those submits probably don't even exist in that build.
