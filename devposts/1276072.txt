At the base, the entire system is a 6DOF acceleration model, so every different pilot control mode is overlaid onto that base model.  In the case of coupled versus decoupled, there are two different blocks of code where input is being translated into control action.  I think the modes are different enough that this is warranted.  But the difference between the modes is encapsulated in about 20 lines of code within the input processing system.
Acceleration control is only currently available in decoupled mode because this was what design asked for.  The system is designed to be very flexible so that various intput modes like acceleration, velocity and positional control could be mapped to any player input.  But at the moment, it is the designers who decide what particular input systems to support in the game.  I have discussed having a redundant fallback mode, which would become available if IFCS is entirely switched off, or if the system malfunctions, which would support raw acceleration control on all 6 axes of control.  This would be very easy to do, and I have supported it in prototype form as far back as 1.3.  And like I've said, I'm in favor of being able to switch off any of these IFCS control blocks (gravity compensation, anti-slide, anti-tumble, etc.) if the pilot wants to do it and believes he or she can do a better job of managing these aspects of ship control.  So it's just a question of what our designers are willing to expose to the players.  The system was designed with this flexibility in mind.
