Sure.  The fix is to split IFCS into two parts.  One part is the control logic, where IFCS determines what state the ship should be in at any given moment based on player input and other criteria.  The other part is the physics processing where IFCS calculates the necessary forces in order to achieve the desired control state determined by the control logic.  The control logic is the bulk of the load in IFCS, so it must remain in the lazy batch update.  But the physics processing needs to be done once every physics step to guarantee stability.
For example, say the player pushes the throttle from 0 to maximum velocity.  When the next IFCS control update occurs, IFCS will set the goal velocity to maximum velocity on the +y axis.  Then the next physics step, the physics processing will calculate the force needed in order to transition the velocity from the current value to the goal value.  There will typically be multiple physics steps between each IFCS control update, which is necessary in order for the physics updates to be perfectly smooth and stable.
I've finished this conversion for all IFCS control except for Gravlev.  I am working on that next, which will include fixing the system in general, since it was broken in 3.0 release and remains broken in 3.1 (due to failing raycasts).  I expect this to be available in 3.2 release.
