Spectrum is using a JavaScript framework made by Facebook called React (https://reactjs.org/), which allows you to create complex web applications while maintaining deterministic state updates. It's a very generic framework which can be used for just about anything that has a UI and requires UI updates, but you're still responsible for implementing all the views, and the state structure and state updates. So we aren't using any forum engine created by Facebook.
Believe it or not, you actually can't check the mouse cursor position at an arbitrary time with the browser's API. You can attach an event listener to mouse moves, but then you have to store the mouse's position and either update it on every frame or risk having out of date information. Determining the identity of an application entity using the HTML element at a particular XY-position is not the cleanest way to do things anyway, since the application state and the browser's DOM tree are not exactly synonymous. You could attach event listeners for mouse enter/leave on every thread list item though, and toggle some value that enables/disables live updates, but you could still run into a situation where the user is moving their mouse towards a thread list item and it updates before their mouse cursor intersects the container. Human reaction time being what it is (>250ms), they could easily click on it before realizing it's now a different thread.
It would be interesting to examine how Facebook handles this though. They may just accept the tradeoffs.
